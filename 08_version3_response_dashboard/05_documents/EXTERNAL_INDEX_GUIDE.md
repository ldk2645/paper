# 外部“微博热搜×领导留言板”指数适配指南

## 1. 先给结论

这个对比指数在方法上可以做，但当前项目**还没有可以据此计算现实结论的数据**。

V3提供的 [build_hotspot_demand_index.py](../02_experiment_code/build_hotspot_demand_index.py)只是离线适配器：它不联网、不登录、不抓取网页，只读取研究者已经合法取得、统一口径、去除个人信息的本地CSV。当前仓库没有一组同时满足以下条件的真实输入：

- 微博热搜与领导留言板覆盖相同日期；
- 使用可比较的地区范围；
- 使用同一套主题分类；
- 数据获取和再利用得到明确许可；
- 不含可识别个人信息；
- 具有可审计的缺失、筛选和聚合记录。

因此，目前只能说“指数定义和适配接口已经实现，并可用合成或受控输入检查”，不能说“已经用微博和领导留言板验证了模型”。

## 2. 三个对象分别是什么

| 符号 | 适配器来源值 | 含义 | 不代表什么 |
|---|---|---|---|
| (H) | `weibo_hot` | 某时间窗内平台热点主题的加权分布 | 全体公众真实偏好、问题严重性 |
| (D) | `leader_board` | 某时间窗内进入领导留言板数据范围的制度化诉求分布 | 所有公民诉求、未公开或未留言人群 |
| (G) | `government_daily`，可选 | 同期政府公开发布信息的主题分布 | 政府内部究竟看到了什么、官员认知或意图 |

用户提出的“政府看到的热点榜单和老百姓真实诉求榜单”在公开数据下应改写为两个可观测问题：

1. 平台热点分布 (H) 与制度化公开诉求分布 (D)有多大偏离？
2. 政府公开发布分布 (G)更接近 (H)还是 (D)？

公开发布数据不能直接证明政府“看见了”某榜单。若要研究政府实际接收、阅读或处置的信息，需要政府内部日志或明确授权的数据，本适配器没有这些数据。

## 3. 公开入口与授权边界

可用于理解数据语义和评估获取条件的入口包括：

- [微博实时热搜榜](https://s.weibo.com/top/summary?cate=realtimehot)
- [微博热搜相关问题说明](https://kefu.weibo.com/faqdetail?id=21636)
- [人民网领导留言板](https://liuyan.people.cn/)
- [领导留言板数据报告](https://leaders.people.com.cn/GB/178291/462227/index.html)
- [领导留言板帮助与用户规则](https://liuyan.people.com.cn/help)

这些网页可公开浏览，不等于具有开放数据许可，也不等于允许自动化批量采集、保存全文或再发布。领导留言板页面还包含明确的版权和使用说明。实际采集前应由数据负责人确认服务条款、版权、个人信息保护和研究伦理要求；若边界不清，应取得书面授权、使用正式数据合作渠道，或只使用明确许可的聚合报告。

V3仓库没有微博或领导留言板爬虫，也不应通过绕过登录、验证码、访问控制或反自动化措施来补数据。

## 4. 内部模型诊断与外部现实指数不能混用

### 模型内部诊断

`model_v3.py`在四个模拟议题上比较：

- 信息池热度分布；
- 当前模拟偏好分布；
- 初始化模拟偏好分布。

内部主要偏离指标是0到1的总变差距离，另有归一化Jensen–Shannon散度、Top-2重合率和Top-1一致率。

### 外部现实指数

外部适配器比较真实输入中统一编码后的 (H)、(D)和可选 (G)，主要输出为0到100的对齐度、盲区度和覆盖率。

二者的对象、主题空间、量纲和尺度都不同，不能直接把内部0.3解释成外部30分，也不能用一个外部指数值校准某个 `alpha`。外部指数若将来建立，只能作为独立描述性证据；要把它用于模型校准，还需要预先规定映射目标、损失函数、训练/验证切分和不确定性传播。

## 5. 严格输入格式

适配器只接受包含以下**精确列集合**的本地CSV。缺列或多列都会报错，以降低个人信息误入结果的风险。

| 列 | 类型/例子 | 规则 |
|---|---|---|
| `source` | `weibo_hot` | 只能是 `weibo_hot`、`leader_board`、`government_daily` |
| `observed_at` | `2026-06-01T08:00:00+08:00` | 必须是可解析、含日期的时间；内部统一到Asia/Shanghai |
| `region` | `全国`或省级名称 | 三来源必须使用预先规定的同层级口径 |
| `topic` | `公共服务` | 必须来自统一主题代码本 |
| `rank` | `1` | 排名加权时微博行必填且大于0；其他来源可空 |
| `heat` | `582341` | 热度加权时微博行必填且不小于0；其他来源可空 |
| `count` | `12` | 聚合频数，可空；填写时必须大于0 |
| `record_id` | `wb-20260601-0800-001` | 数据集内部唯一的记录标识，不得使用用户账号 |
| `access_route` | `authorised_export` | 记录合法取得路径 |
| `license_note` | `research use authorised ...` | 记录许可、协议或限制 |
| `data_scope` | `synthetic_test` | 明确标记合成、授权真实或其他范围 |

禁止放入标准CSV的内容包括：用户名、昵称、手机号、邮箱、留言正文、图片、视频、精确住址、经纬度、设备标识及其他可回溯个人的组合字段。

唯一性键为：

```text
source + observed_at + region + record_id
```

`data_scope`不能留空。合成检查必须标记为 `synthetic_test`或同样明确的值，不得伪装成现实观测。

## 6. 主题代码本

跨平台比较最困难的不是公式，而是把两个平台映射到同一主题空间。正式数据工作应先冻结代码本，再看指数结果。建议流程：

1. 预先确定研究地区和日期，不根据结果回选窗口；
2. 建立互斥程度尽可能高的主题及“无法判定”规则；
3. 用独立样本训练或修订分类规则；
4. 对正式样本采用双人编码，或让自动分类只提供建议、由人工复核；
5. 报告编码一致性和冲突处理；
6. 将无法可靠编码的记录单独报告，不能静默删除；
7. 微博、留言板和政府发布必须使用同一代码本版本。

若直接沿用V3内部的四议题，必须解释为何现实内容可被可靠压缩为这四类。更细的外部主题空间通常更合理，但它与ABM四主题指标的数值就更不能直接相比。

## 7. 时间、地区与选择口径

### 时间

默认窗口为7个完整日历日。适配器只有在完整窗口形成后才输出结果，缺失观测日按零记录进入窗口，而不会偷偷把7天缩成有数据的3天。因此，数据采集故障和真实零记录必须在元数据中区分。

微博热搜变化很快，单日一次截图可能漏掉大量短时热点。应预先规定固定抓取频率或使用得到授权的历史快照；领导留言可能存在审核、转交、公开和回复时延，需明确 `observed_at`使用提交时间、公开时间还是回复时间。

### 地区

微博全国热搜与某一城市的留言不能直接比较。可选设计包括：

- 全国热搜对全国汇总留言；
- 省级同地区榜单对省级留言；
- 在无法获得同地区平台榜单时，明确把结果称为“全国注意力—地方诉求差异”，而不是地区对齐度。

### 选择偏差

微博热搜受平台排序、用户搜索、内容治理和事件供给影响；领导留言板受数字接入、留言意愿、审核公开、平台分类和办理流程影响。(D)应称为“进入研究数据范围的制度化公开诉求”，不应称为全体老百姓的真实需求总体。

## 8. 权重和滚动分布

### 微博热点权重

适配器支持三种模式：

1. `rank`，默认：
   \[
   w_i=\frac{count_i}{\log_2(rank_i+1)};
   \]
2. `heat`：
   \[
   w_i=count_i\log(1+heat_i);
   \]
3. `count`：每条或聚合频数直接计权。

排名权重降低榜尾影响，但仍是研究设计选择，不是微博官方曝光概率。正式分析应至少对 `rank`与可用的 `heat`权重做敏感性比较。

### 领导留言板与政府发布

每行默认计1；若输入已经按日期、地区和主题聚合，则使用 `count`。不得同时保留逐条行又填写重复聚合频数。

在每个完整窗口、地区和来源内，权重归一化为主题份额：

\[
p_k=\frac{w_k}{\sum_j w_j}.
\]

只有同时存在正质量的微博和领导留言板分布时才计算核心指数；政府发布分布是可选项。

## 9. 指数定义

### 9.1 热点—诉求Jensen–Shannon散度

令 (M=(H+D)/2)，使用以2为底的对数：

\[
JSD_2(H,D)=\frac12 KL_2(H\Vert M)+\frac12 KL_2(D\Vert M).
\]

其范围为0到1。

### 9.2 对齐度

\[
Alignment_{HD}=100\left(1-\sqrt{JSD_2(H,D)}\right).
\]

100表示主题分布相同，0表示完全互斥。

### 9.3 盲区度

\[
BlindSpot_{TV}=50\sum_k|H_k-D_k|.
\]

范围0到100；越高表示平台热点与制度化诉求越不一致。

### 9.4 Top-K诉求覆盖率

先取得微博热点份额最高的K个主题，再计算它们覆盖了多少留言诉求质量：

\[
Coverage@K=100\sum_{k\in TopK(H)}D_k.
\]

它回答“热点榜前K类覆盖多少制度化诉求”，不是分类准确率。

### 9.5 主题可见性缺口

\[
Gap_k=100(D_k-H_k).
\]

正值表示该主题在留言诉求中的份额高于热点份额，可能是平台注意力盲区；负值表示热点份额更高。

### 9.6 政府HotBias

若有同期政府发布主题分布 (G)：

\[
HotBias=Alignment(G,H)-Alignment(G,D).
\]

- 正值：政府公开发布更接近热点分布；
- 负值：更接近制度化诉求分布；
- 接近0：两者接近程度相似。

这衡量政府“发了什么”，不能证明政府“看到了什么”，也不能单独识别追随热点或回应诉求的因果机制。

## 10. 运行与输出

命令示例：

```powershell
python 08_version3_response_dashboard/02_experiment_code/build_hotspot_demand_index.py `
  --input path/to/authorised_standard_input.csv `
  --output-dir 08_version3_response_dashboard/05_outputs/external_index `
  --window-days 7 `
  --top-k 3 `
  --weibo-weight rank
```

输出：

| 文件 | 内容 |
|---|---|
| `rolling_topic_distributions.csv` | 各来源、地区、窗口、主题的滚动权重和份额 |
| `hotspot_demand_index.csv` | 对齐度、盲区度、Top-K覆盖率和可选HotBias |
| `topic_visibility_gap.csv` | 每个主题的热点、诉求、政府份额和缺口 |
| `hotspot_demand_index_metadata.json` | 输入路径、SHA-256、范围、参数、公式和无网络声明 |

适配器拒绝URL输入。输出元数据中的 `input_sha256`应与研究归档中的输入快照一致。

## 11. 合成测试与真实分析的标签

合成数据可以检查以下性质：

- 相同分布得到对齐度100、盲区度0；
- 完全互斥分布得到对齐度0、盲区度100；
- 缺列、多列、未知来源、无效时间、负权重和重复主键会被拒绝；
- 缺失日按完整日历规则处理；
- 无政府数据时核心 (H-D)指数仍可计算，政府指标为空。

合成测试只能验证代码和数学边界，不能验证指标在现实中的构念效度。所有合成输入及其输出必须保留 `data_scope=synthetic_test`，不能出现在“真实数据结果”表中。

## 12. 何时才能称为外部验证

至少满足以下条件后，才能把结果描述为外部数据分析：

1. 两来源数据取得方式、授权和再利用范围有书面记录；
2. 时间、地区和主题代码本预先固定且可复核；
3. 数据仅保留研究必要的去标识聚合字段；
4. 缺失、审核、公开和采集频率偏差有明确说明；
5. 分类一致性、权重敏感性和窗口敏感性通过检查；
6. 输入快照、代码版本、参数和输出哈希均归档；
7. 结果只被解释为特定平台、特定制度渠道、特定窗口内的对齐关系；
8. 若声称“验证ABM”，还须预先给出外部指标与模型变量的映射、验证阈值和留出样本。

当前项目尚未满足第1项所要求的真实成对数据条件，因此外部模块的正确表述是：**离线指数适配器与合成测试能力已经准备好，真实数据采集、授权与外部验证尚未完成。**
