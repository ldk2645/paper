## 1. 每日政府发布

V3固定：

```text
enable_routine_government_publication = True
publish_interval = 1
```

日常政府议题继续按V2继承的政府议程主题顺序轮换，内容来源标记为 `government`。请愿回应来源标记为 `government_response`，不计入“每日1条”的日常配额，因此回应日有两条政府来源新信息。

V3在运行时检查每步是否恰好新增一条日常政府信息；完整300步运行必须累计300条。每次日常发布也进入事件日志。

没有新增强制推荐位或强制阅读规则。新信息的初始热度、情绪强度、平台排序和公众互动仍遵循继承参数，所以发布量不等于曝光量。V3新增四个来源特定指标：

- `routine_government_attention_share`
- `routine_government_reach_share`
- `response_government_attention_share`
- `response_government_reach_share`

## 2. 回应热度因子

V3的两组都执行完整政府回应流程：达到10,000签名里程碑、排程、等待、到期发布回应信息、记录 `no_policy_change`，并保证同一请愿最多回应一次。

唯一处理差异为：

```text
response_heat_100: petition_heat <- petition_heat * 1.00
response_heat_070: petition_heat <- petition_heat * 0.70
```

因此：

- 1.00是“回应但不强制降温”，不是“无回应”；
- 0.70隔离的是一次性的30%强制降温机制，不代表现实估计值；
- 两组的 `direct_response_trust_signal`均为0，回应不会被直接编码成增信；
- 两组的 `response_disposition`均为 `no_policy_change`，发布回应不等于采纳诉求。

V3在政府行动阶段保存立即热度前后值。逐步记录中的普通 `petition_heat`则是在同一天又经过平台推荐和公众互动之后记录，不能替代立即热度字段。

## 3. 回应后14日结果

V3新增事件对齐结果：

- 回应日结束热度；
- 回应后14日请愿热度AUC和峰值；
- 回应后14日请愿曝光量和互动量；
- 回应后14日平均信任和平均议程偏离；
- 回应后14日回应信息注意力份额。

同时保留开放期、越过10,000门槛至关闭期的热度、信任和议程偏离摘要。Pilot主要估计量使用回应后14日热度AUC的 `log1p`，避免把相差46天的早晚回应直接放到不同长度的日历窗口中比较。

## 4. 模型内部热点—潜在诉求诊断

V3在每步记录：

1. 按当前信息热度聚合的热点主题分布；
2. 公众当前平均偏好分布；
3. 同一批公众初始化时的平均偏好分布。

两套诉求代理用于区分：当前偏好可能已经受到推荐和偏好漂移影响，而初始化偏好提供一个不随时间变化的模型基线。V3计算：

- 总变差距离：0表示分布一致，1表示完全分离；
- 归一化Jensen–Shannon散度：0表示一致，1表示完全分离；
- Top-2重合率；
- Top-1一致率；
- 完整主题排序相关。

这些是模型状态诊断。它们既不是政府真实后台所见榜单，也不是对真实公众诉求的观测。`government_dashboard_mode="compare_only"`确保诊断不会改变政府发布主题，从而不污染本轮回应热度对照。

## 5. Pilot与正式设计

### 已完成pilot

- `alpha={0.40,0.60,0.80}`；
- 11天早回应与57天晚回应；
- 10个共同种子；
- 热度乘数1.00与0.70；
- 共120次、36,000条逐步记录。

Pilot清单将证据状态标记为 `exploratory_pilot_not_formal_evidence`。它用于确认30%立即热度干预确实执行、配对任务完整、每日发布计数正确，以及早晚差异是否存在值得正式检验的信号。

### 尚未运行的正式设计

- 3、11、22、57天和条件经验重抽样，共5种时延；
- 21个 `alpha`；
- 50个共同种子；
- 2个热度乘数；
- 共10,500次。

V3没有把pilot扩写成正式结论，也没有生成或冒充正式结果文件。

## 6. 外部指数适配器

新增 `build_hotspot_demand_index.py`。它：

- 不联网、不抓取网站；
- 拒绝URL，只读取本地CSV；
- 要求严格、去个人信息、含来源和许可说明的列结构；
- 可比较 `weibo_hot`、`leader_board`及可选的 `government_daily`；
- 输出滚动主题分布、对齐度、盲区度、Top-K覆盖率、政府 `HotBias`和主题缺口。

当前仓库没有符合要求的真实微博—领导留言板成对数据，因此这项新增只是方法和适配接口，不构成外部验证。公开网页可浏览也不自动意味着允许批量采集或再发布。

继承不表示这些机制已经被英国案例或中国外部数据重新校准。

## 已知限制

1. 每日一条政府信息是研究设计规则，不是由现实政府发布频率估计得到。
2. 日常政府信息默认初始热度仍很低，实际曝光取决于推荐竞争；不能用发布数推断触达。
3. 0.70是反事实敏感性值，不是回应降温的经验因果估计。
4. 同一随机种子保证相同初始化，并使同一时延的两热度组在回应前轨迹相同；不同回应日会改变后续信息池，从而使早晚组回应后的随机路径不再是逐随机数完全对应。
5. 模型潜在偏好不是领导留言板留言，也不能代表未上网、未留言或未公开群体。
6. 外部适配器尚无合规真实成对数据，不能用于声称V3通过了真实微博或领导留言板验证。
