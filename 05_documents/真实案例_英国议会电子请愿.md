# 真实案例嵌入方案：英国议会电子请愿

> 文档用途：详细解释候选案例、说明选择理由及候选案例的优缺点，并提供加入案例后可直接修订进论文的第4.4节和第4.5节预览。<br>
> 证据定位：本案例是“案例约束的机制重建”，不是对完整智能体模型的现实验证。<br>
> 数据时点：项目现有英国请愿快照于2026年8月1日18:54 UTC获取；文中的签名数是该快照时的累计值。
> 发布状态：本次GitHub更新仅纳入案例设计和论文拟稿；英国请愿原始快照、处理表及分析脚本尚未并入该发布包。本文中的统计量已与项目工作目录的现有验证输出核对；若执行正式案例实验，还需将快照元数据、SHA-256、处理数据和代码一并归档。

## 1. 结论先行

本项目建议选择**英国议会电子请愿系统**作为论文的主案例，并采用“222条已回应请愿的总体分布＋请愿700024的完整时间线”两层写法。

选它的核心理由不是“这是一个热门事件”，而是该制度提供了模型最关键链条的官方时间戳：

> 公众签名和注意力累积<br>
> → 越过10,000签名的制度门槛<br>
> → 制度上触发政府回应规则<br>
> → 经过可计算的延迟<br>
> → 责任政府部门发布正式回应。

这与项目的“公众—平台—政府”三方链条在**门槛触发—延迟回应这一子链**上具有对应关系，又不依赖空间网格和邻域扩散，因而适合当前冻结的非空间模型。但英国请愿网站不是典型的个性化社交媒体，数据中也没有政府内部排程记录、个体曝光、偏好漂移或政府信任测量；因此它只能直接约束“制度门槛时间—政府回应时间”，不能识别推荐权重 \(\alpha\) 或证明政府回应必然降温。

## 2. 借鉴参考文献的方法：案例不是装饰性背景

Bitterman和Koliba在尚普兰湖流域水治理研究中，不是先完成一个抽象模型，再在讨论部分附加一个真实地名。他们把真实的行政单位、环境目标、工程项目、审核能力与政策备选方案映射到模型中，再比较不同治理制度的反事实结果。本项目应借鉴的是如下证据链：

1. 从可核验的真实制度问题出发；
2. 明确真实行为、数据字段与模型变量之间的对应；
3. 将可观测的部分用于约束情景，将不可观测的部分保留为反事实政策参数；
4. 不只看最终指标，还观察“门槛越过、模型内待回应积压、回应延迟、回应后热度”等中间机制；
5. 把模型输出回放到真实制度语境中解释；
6. 明确列出不能识别和不能外推的内容。

因此，英国请愿案例的功能是为“公开门槛触发政府回应规则”提供真实制度原型，并为门槛到回应的观测时延提供经验范围。模型再将这一制度规则操作化为待回应状态和排程；这部分是模型设定，不是API直接观测到的政府内部流程。

## 3. 案例详解

### 3.1 英国议会电子请愿制度如何运行

英国议会电子请愿系统由英国议会与英国政府共同运行。英国公民或英国居民可以在官方网站提出要求政府或议会采取行动的请愿。请愿经初始支持与审核后公开，通常保持开放六个月，公众可以在线签署和转发。

制度设置了两个公开门槛：

- 达到10,000个签名后，负责该议题的政府部门需要作出正式回应；
- 达到100,000个签名后，请愿将由议会请愿委员会考虑是否安排辩论；越过该门槛不等于必然辩论。

网站在此过程中承担信息准入、审核、公开展示、搜索排序、签名计数和状态更新等中介功能。它将分散的个人签名转换为政府可监测的聚合注意力，因此可以被视为“制度化信息中介”或“注意力基础设施”。但本项目没有个体层面的曝光日志，也没有证据显示它使用本模型的“热度—相似度”个性化公式。

### 3.2 数据来源、样本和变量转换

案例数据来自英国议会官方请愿API。项目通过 `petitions.json?state=with_response` 分页获取357条已有政府回应状态的请愿，提取请愿编号、标题、负责部门、公开时间、达到10,000签名时间、政府回应时间和快照签名数。

为避免随查询日期漂移，分析固定了一个与抓取日期无关的样本窗口：达到10,000签名的时间需满足

\[
2024\text{-}07\text{-}01\leq T_i^{threshold}<2026\text{-}01\text{-}01.
\]

仅保留门槛时间和回应时间都完整的记录，最终得到222条请愿。主要转换如下：

1. 条件回应时延

   \[
   D_i=\frac{T_i^{response}-T_i^{threshold}}{24\text{小时}}.
   \]

2. 从公开到越过10,000签名所需的天数

   \[
   G_i=\frac{T_i^{threshold}-T_i^{open}}{24\text{小时}}.
   \]

3. 达到门槛前的平均签名速度代理量

   \[
   V_i=\frac{10{,}000}{G_i}.
   \]

   \(V_i\)是区间平均速度，不是根据逐日签名日志得到的即时传播速度。

4. 30天内回应指标

   \[
   R_i^{30}=I(D_i\leq30).
   \]

222条请愿的条件回应时延如下：

| 统计量 | 数值 |
|---|---:|
| 样本数 | 222 |
| 最小值 | 6.21天 |
| 第5百分位 | 11.07天 |
| 第25百分位 | 15.38天 |
| 中位数 | 21.65天 |
| 平均数 | 24.41天 |
| 第75百分位 | 26.72天 |
| 第95百分位 | 56.52天 |
| 最大值 | 128.01天 |
| 30天内回应比例 | 81.98% |

这一分布说明，政府回应存在可观测且具有异质性的等待期。若把一个模拟步解释为一天，则冻结模型默认的 `response_delay=3` 低于该条件样本的最短回应延迟6.21天，不应被解释为英国请愿系统的典型回应速度。

快照签名数与回应时延的Spearman相关为 \(\rho=-0.0580\)，置换检验 \(p=0.3946\)，Bootstrap 95%置信区间为 \([-0.1831,0.0723]\)；越过门槛前平均签名速度与回应时延的相关为 \(\rho=-0.0797\)，\(p=0.2386\)。两项分析都没有显示“热度越高，政府回应越快”的清晰经验关系。第一项尤其只能描述，因为快照签名数是越过门槛后仍可继续增长的结果量。

### 3.3 回应时延中位附近的说明性个案：请愿700024

用于展示制度过程的单案是 **Ban fossil fuel advertising and sponsorship**（“禁止化石燃料广告与赞助”），请愿编号为 **700024**。其诉求是由英国政府禁止化石燃料广告和赞助，理由是此类广告可能建立化石燃料企业的社会接受度，并通过“漂绿”弱化公众对气候风险的认识。

| UTC时间 | 真实事件 | 在模型中的解释 |
|---|---|---|
| 2024-10-30 15:38 | 请愿创建 | 议题或信息对象形成，但尚未公开 |
| 2024-10-30 16:02 | 达到初始审核门槛 | 进入平台准入流程 |
| 2024-11-12 10:44 | 请愿正式公开 | 进入公众可见的信息环境 |
| 2024-11-26 17:33 | 达到10,000签名 | 制度上触发政府回应规则；模型将其操作化为回应排程 |
| 2024-12-18 12:35 | 政府发布正式回应 | 经过延迟后执行政府行动 |
| 2025-05-08 21:30 | 达到100,000签名 | 进入更高层级的议会审议考虑流程 |
| 2025-05-12 22:59 | 请愿关闭 | 公众签名窗口结束 |
| 2025-07-07 | 英国议会辩论 | 更高层级的制度行动；当前核心模型尚未单独建模 |
| 官方快照记录 | 110,519个签名 | 越过两个公开门槛 |

从正式公开到越过10,000签名用时约14.28天；从越过10,000签名到政府回应用时约21.79天；从公开到政府回应共约36.08天。负责回应的机构是英国能源安全与净零部。

政府回应承诺继续降低高碳产品排放，但表示当时没有限制化石燃料广告的计划。这是本案例最有价值的质性信息之一：**“政府已回应”、“政府接受诉求”和“政府回应使议题降温”是三件不同的事**。该请愿在政府回应后仍继续增长，并在2025年5月越过100,000签名门槛。但由于官方API没有提供完整的逐日签名轨迹，不能由此估计回应对热度的因果效应。

### 3.4 单案选择规则为何可复核

222条请愿的回应延迟中位数是21.646天。700024的延迟是21.793天，两者相差约0.147天。由于222是偶数，样本中位数是两个中央观测值的平均；700024是这两个中央观测之一。因此，它可以称为**在政府回应延迟这一维度上接近中位水平的说明性案例**。

在两个中央观测中进一步选择700024，是因为它的公开生命周期已经完成，并且同时经历了平台审核、正式公开、10,000签名、政府回应、100,000签名、请愿关闭和议会辩论。这一次级选择是为了展示完整制度链，不是认定该议题在传播规模或政策结果上代表普通请愿。其最终签名数达到110,519且实际进入议会辩论，恰恰意味着不能把它称为“所有特征都典型”的请愿。该规则是为本次案例说明而明示化的选择规则，不是外部预注册规则，因而不能完全消除事后选案风险。正式推断仍以222条总体分布为主，单案只负责展示过程。

本研究也没有选择快照签名数为3,084,713的700143号“Call a General Election”作为主单案。这类极端高热度请愿适合另做极端案例对照，但如果用它代表一般请愿，会同时放大政治议题特殊性和传播规模偏差。

### 3.5 三方主体和模型变量的对应

| 现实对象或事件 | 模型对象 | 案例可以提供的证据 | 不能从案例直接得到的内容 |
|---|---|---|---|
| 能源安全与净零部 | 政府智能体 | 责任部门、制度回应规则与精确回应时间 | 政府内部监测/排程、回应必然降温、`response_strength=0.70`所表示的“回应后热度保留率” |
| 英国议会请愿网站 | 平台智能体 | 信息准入、公开展示、状态更新、签名计数 | 个性化曝光、推荐公式与 \(\alpha\) |
| 请愿发起者与签署者 | 公众智能体 | 聚合参与与签名累积 | 个体偏好、真实曝光、偏好漂移和信任变化 |
| 请愿700024 | 自发信息或议题对象 | 完整生命周期与制度事件 | 与模型中每条内容一一对应 |
| 签名数 | 热度代理量 | 累计参与强度 | 浏览、点击、转发和签名是否等价 |
| 10,000签名 | 政府回应触发事件 | 门槛在制度上触发政府回应规则；模型将其类比为排程 | 与模型15%回应排程门槛的数值换算 |
| 门槛和回应时间戳 | `response_delay` | 回应延迟的条件分布 | 所有议题都有同一固定延迟 |
| 政府回应文本 | 政府回应事件 | 回应是否发生、回应部门与质性立场 | 回应强度的数值效果 |
| 100,000签名与议会辩论 | 更高层级的制度行动 | 可用于后续扩展 | 当前核心模型没有单独的议会智能体 |

这一映射中最重要的两个边界是：第一，现实的10,000签名是累计绝对数，模型 `response_threshold=0.15` 判断的是“某议题自发信息的本步消费次数/本步全部信息消费次数”是否严格大于0.15，且默认Hard策略遍历所有议题，而不是只监测政府议程外议题。两个门槛的分子、分母、时间口径与含义都不同；第二，模型内政府信任是潜变量，而请愿数据没有对应的信任问卷，因此案例输出的信任只能解释为模型内部结果。

### 3.6 案例到底能支持什么

| 命题 | 证据等级 | 理由 |
|---|---|---|
| 政府回应可以由公开注意力门槛触发 | 直接支持 | 官方规则明确规定10,000签名后政府回应 |
| 越过门槛与回应发布之间存在延迟 | 直接支持 | 222条记录都有两个时间戳 |
| 回应延迟具有异质性 | 直接支持 | 条件时延为6.21–128.01天 |
| 平台决定请愿是否以及何时公开可见 | 直接支持 | 官方记录创建、审核门槛与公开时间 |
| 公开展示会如何影响后续签名 | 不可识别 | 无个体曝光日志和可比反事实 |
| 签名规模越高，政府回应越快 | 未获清晰支持 | 两项相关接近0且区间跨越0 |
| 政府发布回应必然使热度下降 | 不可识别 | 无逐日热度轨迹，单案仍继续越过更高门槛 |
| 个性化推荐权重 \(\alpha\) 的真实值 | 不可识别 | 无推荐算法或个体曝光数据 |
| 公众偏好漂移和政府信任变化 | 不可识别 | 数据为聚合请愿记录，无面板问卷 |

## 4. 选择理由与候选案例对比

### 案例选择标准

为防止按“新闻轰动性”选案，候选案例按七个与研究设计直接相关的标准比较：

1. 能否区分政府、平台与公众三类主体；
2. 能否观察公众行为、门槛越过和政府回应时间；
3. 数据来源是否官方、开放且可冻结；
4. 是否可以不依赖当前已排除的空间扩散机制；
5. 是否可与现有非空间核心模型对接，而不必重写主体架构；
6. 是否存在无法接受的个人隐私或灾害伦理风险；
7. 是否能够形成可审计的数据—转换—模型链。

### 相对其他案例的优势

- **比郑州“7·20”暴雨更容易复现。** 英国请愿的制度边界、字段和回应定义统一，不依赖难以完整重建的历史微博爬取。
- **比Hurricane Harvey更符合单一政府智能体的设定。** 后者涉及FEMA、地方机构、志愿者和民间救援网络，强行压缩为一个政府主体会丢失关键机制。
- **比UCI公共事务新闻更完整。** 英国请愿确实包含责任政府部门和正式回应，而不只是新闻传播与公众互动。
- **比NYC 311更接近“公众注意力—政府回应”。** 311的关闭字段主要是行政工单状态，不一定是面向公众的政府立场文本；英国请愿的回应与请愿在同一官方页面上直接配对。
- **与当前正式模型的版本边界一致。** 英国请愿的主要可观测机制是全国统一的制度门槛和门槛到回应的时间差，不要求恢复已从正式设计中排除的空间扩散。

### 英国案例自身的缺点

1. 请愿网站不是商业个性化推荐平台，不能识别 \(\alpha\)。
2. 签名表示支持或参与，不等于浏览、点击、转发或偏好变化。
3. 222条样本条件于 `with_response` 状态，无法估计所有越过门槛的请愿最终获得回应的概率，也可能截断未回应者的长时延尾部。
4. 快照签名数在越过门槛乃至回应之后仍可增长，不是外生的“回应前热度”。
5. 10,000签名不能直接换算为模型15%的“议题自发信息消费/全部信息消费”回应排程门槛。
6. 政府回应文本不等于接受诉求、解决问题或提升信任。
7. 官方API没有完整逐日签名轨迹，目前不能估计“政府回应导致热度下降”的因果效应。
8. 请愿数据不包含政府信任量表，不能验证模型中的信任变量。
9. 英国制度环境与中国数字治理环境不同，可迁移的是抽象机制，不是具体参数或政策结论。

### 综合取舍

英国案例并不在所有维度上胜出：UCI数据对情绪、互动和注意力衰减的观察更好；郑州和Harvey对空间扩散、人际传播和应急网络更真实；NYC 311对行政处理延迟和地理异质性的观测更细。英国案例的优势是在当前非空间版本下，它对“制度门槛—延迟回应”的观测最清晰，可复现性和伦理负担也最均衡。

因此建议的组合方案是：

- 英国议会电子请愿作为主案例，负责门槛触发、回应延迟和回应语义的现实化；
- UCI数据继续留在S1：`News_Final.csv`用于情绪—互动分析，`Facebook_Obama.csv`和`Facebook_Palestine.csv`用于24小时注意力衰减分析；
- 世界银行和OECD数据继续负责数字政府与宏观信任的描述性对照；
- 郑州、Harvey和NYC 311保留为空间版本或后续外部有效性扩展，不强行并入当前核心实验。

## 5. 加入案例后的论文预览

下面两节按可直接纳入论文的口径撰写。第4.4节报告仓库中已完成的正式实验；第4.5节中的请愿描述统计是已完成结果，而“案例约束情景实验”是下一阶段设计，在实际运行之前不应改写为已发现的模拟结果。

### 4.4 消融、稳健性与外部一致性检验

为区分推荐规则的总体效应与具体行为机制的边际作用，本研究以冻结的非空间完整模型为基准，设置完整模型、无情绪优势、无偏好漂移、无有效政府回应和无信任—互动反馈五个正式条件。其中前四个条件来自原正式协议，共4,200次运行；`No trust`是后续按同一 \(\alpha\) 网格和随机种子补入的1,050次正式消融，合并后共5,250次。历史前四条件与`No trust`的运行环境并非逐比特完全相同，因此复现性说明保留该溯源边界，不将后者写成原协议预设条件。

每个条件扫描 \(\alpha=0.00,0.05,\ldots,1.00\) 共21个水平，每个组合采用共同随机种子73000–73049重复50次。单次运行包含300名公众智能体和300个时间步，主要结果使用末100步稳态窗口汇总。相同种子编号用于对齐可对齐的随机初始化并构造配对比较；机制分支可能使后续随机调用路径产生差异，因此不声称不同条件的每一个随机数都逐项同源。

主要观测指标包括平均议程偏离、偏离度方差、舆情风暴时间占比和平均政府信任。其中 `system_stability` 在代码中实际表示末100步议程偏离的方差，数值越大意味着波动越强，不能按字面解释为“系统越稳定”。条件差异使用共同种子配对差、95%置信区间、Hedges \(g_z\)和双侧Wilcoxon符号秩检验报告，并对同簇比较进行Holm校正。

五条件的议程偏离临界点估计分别为：完整模型0.60 \([0.55,0.60]\)，无情绪优势0.75 \([0.60,0.80]\)，无偏好漂移0.60 \([0.55,0.75]\)，无有效政府回应0.60 \([0.60,0.60]\)，无信任—互动反馈0.60 \([0.55,0.60]\)；括号内为以种子整条 \(\alpha\) 曲线为区组的5,000次Bootstrap 95%置信区间。在预先关注的 \(\alpha=0.60\) 处，与完整模型相比，无情绪优势使议程偏离平均下降0.2228、风暴时间占比下降0.540、政府信任上升0.03845；无偏好漂移使议程偏离下降0.11165、偏离度方差增加 \(1.10\times10^{-4}\)、信任上升0.00987，其风暴时间占比增加0.1072的全局Holm校正符号翻转 \(p=0.195\)，未显示清晰多重校正证据；无有效政府回应使议程偏离下降0.03046、偏离度方差下降 \(3.45\times10^{-5}\)，但信任下降0.01542。

`No trust`结果需要特别谨慎解读：其在 \(\alpha=0.60\) 处的议程偏离配对差为−0.01969，Bootstrap 95%区间为 \([-0.03613,-0.00337]\)，但全局Holm校正符号翻转 \(p=0.17276\)；信任配对差为+0.00170，Bootstrap区间为 \([-0.00074,+0.00418]\)。因此，不应仅因第一个Bootstrap区间未跨越0就宣称信任反馈存在经全局多重校正的明确主效应。

补充稳健性分析进一步检查14组参数扰动、2种替代回应策略和3种执行顺序，新增19,950次模拟；与完整模型和无有效回应参照合并后，分析输入为22,050行。14组参数扰动的临界点估计位于0.55–0.65；其中只有将回应门槛从0.15提高到0.30时，临界点明确移至0.65，相对完整模型的配对位移95%区间为 \([+0.05,+0.10]\)。三种替代执行顺序的临界点位于0.55–0.60，其配对位移区间都包含0。

回应规则对结果的影响不应只用临界点概括。Hard、Selective、Wait和无有效回应条件的 \(\alpha_c\) 点估计都是0.60，但在 \(\alpha=0.60\) 处，Selective相对完整模型的议程偏离增加0.131、信任下降0.0194；Wait的议程偏离下降0.032、信任上升0.0071；无有效回应条件的议程偏离下降0.030，但信任下降0.0154。这表明“临界位置是否移动”、“跳变后的结果水平”和“政府信任如何变化”是不同问题。

外部一致性检查使用世界银行、OECD和UCI公开数据，用于检查数字政府、宏观信任、情绪互动和注意力衰减的方向或数量级是否与模型兼容。这些分析不构成因果识别，也没有把模拟参数估计为现实世界常数。综合而言，消融实验回答“去掉某个机制后模型会发生什么”，敏感性分析回答“主要结论是否依赖某个特定参数或执行顺序”，公开数据检查回答“模型机制是否与部分现实观测相容”。

### 4.5 英国议会电子请愿：案例约束的机制重建

为增强模型的制度可解释性，本研究选择英国议会电子请愿系统作为真实案例。该选择并不意味着英国请愿制度与本模型或中国数字治理情境完全等同，而是因为它为“公众议题越过制度门槛后触发政府回应规则”提供了官方、精确且可复核的门槛与回应时间戳。相较于依赖平台爬取的灾害舆情案例、缺少政府主体的公共事务新闻数据，以及以空间行政工单为核心的NYC 311数据，英国请愿数据能够在不引入空间扩散的条件下，为门槛触发规则和异质性回应延迟提供现实约束。官方数据不显示政府内部队列或排程；这部分是模型对制度规则的操作化。

英国议会请愿网站将政府、平台和公众三方连接起来。公众创建、签署和传播请愿；平台审核、公开展示、计数并更新制度状态；政府部门在请愿越过10,000签名门槛后进入回应流程。达到100,000签名后，请愿还会进入议会辩论考虑程序。这一现实链条与模型中的“公众互动—平台可见性—门槛监测—政府延迟回应”结构对应。

本研究从官方API的 `state=with_response` 查询获得357条已获政府回应的请愿，使用达到10,000签名的时间在2024年7月1日至2026年1月1日之间的固定窗口，并保留门槛和政府回应时间都完整的222条记录。这是API查询过滤条件，不是每条请愿的当前 `state`；例如700024在原始记录中的当前状态是 `closed`。已回应请愿的门槛到回应时延中位数为21.65天，第5和第95百分位分别为11.07天和56.52天，范围为6.21–128.01天，81.98%的已回应请愿在越过门槛后30天内获得回应。快照签名数与回应时延的Spearman相关为−0.0580，区间跨越0；现有证据未显示签名规模越高就必然回应越快。

为展示个案过程，本研究选择请愿700024“禁止化石燃料广告与赞助”。该请愿于2024年11月12日公开，11月26日越过10,000签名，12月18日由能源安全与净零部正式回应，门槛到回应延迟为21.79天，接近样本中位数21.65天。政府在回应中表示当时没有限制化石燃料广告的计划。该请愿之后仍越过100,000签名，并在2025年7月7日进入议会辩论。因此，该案例直接显示“已回应”不等于“政策诉求已被接受”，并说明分析上必须将“议题是否降温”作为第三个、尚未被现有时序数据识别的结果。

在案例约束情景实验中，计划将一个模拟步映射为一个日历日，并仅用英国请愿数据约束“触发后等待时间”，不强行把10,000签名换算为模型15%的回应排程门槛。主实验设置理论基准3步、经验较快回应11步、经验典型回应22步、经验较慢回应57步和条件经验分布重抽样五个延迟条件；其中11、22和57分别是已回应条件样本P5、中位数和P95四舍五入后的整天值。重抽样条件对每个随机种子只抽取一个整天延迟，并在该种子的21个 \(\alpha\) 水平中保持不变，以维持配对性。五个延迟条件均扫描21个 \(\alpha\) 水平，并使用50个共同随机种子。为使五个条件在同一案例运行器和软件环境中生成，3步基准也重新运行，因而计划新增5,250次而不是复用旧基准后的4,200次。每次运行包含300名公众、300个时间步，末100步为汇总窗口，其他参数保持与冻结完整模型一致。需要注意，一旦将一步解释为一天，热度衰减和偏好漂移等逐步参数也会获得“每日”含义；它们并未被请愿数据校准。因此该时间对应是回应延迟情景的时钟约定，不是对全部逐步过程的现实标定；解读时应结合已有衰减率和漂移率敏感性结果。

延迟实验的主要比较指标为议程偏离、风暴时间占比、政府信任、触发到回应的积压期长度和回应前后的议题热度。回应效果不由单案例强制定标；辅助情景将使用冻结代码已有的Hard、Selective、Wait和无有效回应设定，比较不同的触发条件、目标范围和有效热度保留规则。该处理是必要的，因为请愿700024已获得政府回应，却没有获得其主要政策诉求，而且累计签名仍继续越过更高门槛。

这一案例设计能够回答的是：当真实制度中的回应延迟范围代入同一智能体结构时，模型的议程、舆情和信任结果如何改变，以及这些变化是否在临界 \(\alpha\) 附近放大。它不能回答的是：英国请愿平台的真实 \(\alpha\) 是多少、个体偏好如何漂移、政府回应使现实签名数变化多少，或英国经验参数是否可直接外推到中国。因此，本案例应被称为“案例约束的政策原型”，而不是“完整模型的现实验证”。

## 7. 写作与实验边界清单

正文可以写：

- 英国请愿制度为门槛触发和延迟回应提供现实原型；
- 222条已回应请愿中，条件回应延迟中位数为21.65天；
- 700024是在回应延迟维度接近中位数且生命周期完整的说明性案例；
- 政府回应、政策接受和议题降温必须分开建模；
- 案例数据可以约束回应时延情景。

正文不应写：

- 10,000签名证明模型15%回应门槛正确；
- 英国请愿数据估计出了真实 \(\alpha\)；
- 签名增长等同于个体偏好漂移；
- 政府回应使请愿热度下降；
- 请愿数据验证了政府信任机制；
- 222条已回应请愿代表全部请愿的回应概率；
- 英国参数可以不经检验直接外推到中国。

在将案例情景的模拟结果改写为论文过去时结果之前，必须先生成完整原始CSV、参数清单、统计检验、效应量、95%置信区间和图源数据，并用发布QA检查行数、主键、随机种子和文档数值。
