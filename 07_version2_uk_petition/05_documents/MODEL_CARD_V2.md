## 2. 模型用途

V2用于研究这样一个反事实问题：在相同的公众、平台推荐和政府信任动力学下，如果一个公众发起的请愿按现实制度门槛进入政府回应流程，而政府等待时间处于英国已回应请愿的较快、典型、较慢或经验分布水平，系统的议程偏离、舆情风暴、请愿热度和政府信任会怎样变化？这些差异是否会随推荐权重 `alpha` 改变？

适合的用途包括：

- 将“门槛触发—等待—政府回应”作为可审计状态机嵌入三方智能体模型；
- 比较回应时延情景；
- 检查门槛越过、队列积压、回应发布与结果变量之间的模型机制；
- 对回应的热度效应和直接信任效应做明确的反事实敏感性实验；
- 为论文中的英国请愿案例提供可复现的政策原型。

不适合的用途包括：

- 估计英国请愿平台的真实推荐算法或真实 `alpha`；
- 预测某一请愿的最终签名数；
- 估计所有请愿获得回应的概率；
- 识别政府回应对签名、热度或信任的现实因果效应；
- 将英国参数直接外推为中国数字政府参数；
- 代替V1已经完成的正式消融、敏感性或公开数据一致性结果。

## 3. 主体、初始特征与职责

### 3.1 公众智能体

每名公众具有：

- 四个议题上的偏好向量；
- 情绪互动倾向；
- 数字素养；
- 学习成本；
- 政府信任；
- 最近主导议题和连续暴露步数；
- 是否已经签署焦点请愿的布尔状态。

公众接收平台推荐，按内容情绪强度、来源以及自身信任形成互动概率。互动会增加信息热度；持续暴露于同一主导议题可导致偏好漂移。在 `synthetic_unique_support` 模式中，公众只有在请愿开放且被推荐到时才有概率签署，而且每名智能体最多签一次。

公众智能体不是现实签署者的抽样，也没有设置“一名智能体等于若干现实签名”的权重。

### 3.2 平台机制

平台维护信息池并为每名公众计算：

\[
score_{ui}=\alpha\,\widetilde{\log(1+heat_i)}
+(1-\alpha)\,similarity(u,topic_i).
\]

其中第一部分是归一化热度信号，第二部分是公众偏好与内容议题的相似度。V2不改变这一公式，只改变焦点请愿的生命周期：请愿开放时进入候选池，关闭后退出推荐候选；请愿对象本身继续保留在信息池中供事件和最终状态审计。

英国请愿网站没有提供个体曝光日志，也不能识别该公式或 `alpha`。因此平台机制属于从V1继承的反事实表示，不是对英国网站推荐系统的估计。

### 3.3 政府智能体

V2默认关闭V1的定期政府主题发布和“本步主题注意力份额超过0.15”触发器。政府只处理焦点请愿的待回应事项：门槛越过后建立一次待办，等待 `response_delay`，到期后只执行一次正式回应。

回应时，模型：

1. 将焦点请愿热度乘以 `response_heat_multiplier`；
2. 生成一条来源为 `government_response` 的回应信息；
3. 向当步信任更新传入 `direct_response_trust_signal`；
4. 记录回应的政策立场 `response_disposition`；
5. 清空该请愿待办并禁止再次排程。

政府智能体中的“排程队列”是对公开制度的模型化，不是官方API观测到的政府内部工作流。

### 3.4 信息对象

普通信息继承V1字段：议题、情绪强度、热度、来源和创建步。焦点请愿是一个持续性信息对象，另有唯一请愿编号、开放/关闭时间、门槛状态、回应到期日和回应状态。回应发布时生成另一条政府回应信息，但它不替换请愿本身。

## 4. 单步运行顺序

V2继承V1循环，按以下顺序执行：

1. **政府行动**：若待回应任务到期，先发布回应并施加独立热度乘数和直接信任信号；
2. **自发信息生成**：加入本步普通公众信息；
3. **平台推荐**：从当前可见信息池计算热度—相似度混合分数；
4. **公众行动**：消费、互动、热度沉积、偏好漂移；
5. **请愿支持更新**：记录曝光；合成模式抽取新的唯一签署者；
6. **系统测量**：计算议程份额、议程偏离、议程外峰值和风暴状态；
7. **门槛监测**：若首次满足门槛，排程回应；案例日历模式同时记录100,000门槛；
8. **学习和信任更新**：继承V1方程，回应的直接信号作为单独输入；
9. **记录**：写入V1与V2逐步字段；
10. **衰减和清理**：所有信息热度自然衰减，普通低热度信息可清理，焦点请愿对象保留。

由于门槛监测在政府行动之后，同一步刚达到门槛时不会立即执行回应；设触发步为 \(t\)、时延为 \(d\)，回应在 \(t+d\) 的政府行动阶段执行。

## 5. 两种触发模式

### 5.1 `observed_calendar`

该模式用于700024案例约束实验。模型在指定日历步把 `observed_signature_count` 更新到案例里程碑，并在第14步达到10,000后排程回应。第177步记录达到100,000和“可进入辩论考虑”，第182步记录关闭与110,519的官方快照。初始值5只来自英国请愿提交需5名支持者的制度规则，不是API记录的700024公开瞬间签名数。

这不是一条逐日签名增长曲线。5、10,000、100,000和110,519之间的数值阶梯只用于重放已知里程碑，不能用于估计签名速度或回应造成的增长变化。

### 5.2 `synthetic_unique_support`

该模式用于机制实验。每名模拟公众仅能签一次，累计唯一签署者比例为：

\[
s_t=\frac{\sum_u I(\text{公众}u\text{已签署})}{N}.
\]

当 \(s_t\) 第一次达到 `synthetic_support_threshold_fraction` 时排程回应。默认阈值0.20、曝光后签署概率0.02均为研究设计假设。

### 5.3 禁止的换算

现实制度门槛与合成比例的分母、测量对象和数据生成过程不同：

- `observed_signature_count`：现实聚合签名里程碑；
- `cumulative_unique_signers`：300个模型智能体中已签署的人数；
- `synthetic_support_fraction`：后者除以模拟公众数。

三者可并列输出以便审计，但不能互相换算或拼成同一条增长序列。V2没有设置“一个智能体代表多少现实签名”。

## 6. 数据与证据来源

### 6.1 单案700024

官方页面与JSON提供请愿标题、责任部门、公开时间、越过10,000和100,000门槛的时间、政府回应、关闭、辩论及签名快照。V2使用的整数步是将日历间隔取整后的案例参数。政府立场编码为 `no_policy_change`，因为回应表示当时没有限制化石燃料广告的计划。

单案支持的是制度事件顺序和回应是否采纳诉求，不能支持回应对热度或信任的因果效应。

### 6.2 222条已回应请愿条件样本

`03_data/uk_petition_response_delays_222.csv`只包含请愿编号与“10,000门槛时间到政府回应时间”的连续天数。样本由英国议会官方API的 `state=with_response` 查询获得，再按固定门槛时间窗和完整时间戳筛选。条件样本的P5约11.07天、中位数约21.65天、P95约56.52天，据此形成11、22和57天情景。

“条件样本”意味着样本已经限定为获得回应且时间戳完整的记录。它可能遗漏尚未回应的长时延，不能用于估计无条件回应概率。

### 6.3 从V1继承的数据与参数

V2继承V1的WVS、世界银行、OECD和UCI相关标定/一致性链条及模型内部参数，但本次英国请愿CSV只直接进入回应时延场景。V1中的热度衰减、偏好漂移、数字政府、学习成本和信任系数没有用700024或222条请愿重新估计。

### 6.4 反事实参数

`alpha`、合成签署行为、合成门槛、请愿情绪强度、回应热度乘数和直接信任信号没有被英国数据识别。运行器应把这些参数连同来源类别写入配置或运行清单。

## 7. 回应的四维拆分

V2禁止把以下四件事当作同一结果：

| 维度 | 操作化 | 默认案例值 | 能否由案例识别 |
|---|---|---:|---|
| 回应发布 | 到期后生成事件和政府回应信息 | 是，一次 | 能识别是否和何时发生 |
| 政策采纳 | `response_disposition` | `no_policy_change` | 可由回应文本质性编码 |
| 热度效应 | `response_heat_multiplier` | 1.00 | 不能；默认不强制变化 |
| 直接信任效应 | `direct_response_trust_signal` | 0.00 | 不能；无信任量表 |

`response_heat_multiplier=1.00`表示回应执行瞬间不改变请愿热度；小于1表示模型设定的降温，大于1表示模型设定的再升温。它不是“回应强度越大降得越多”的减法系数。

`direct_response_trust_signal=0.00`只表示不额外赋予回应一个直接增信/损信冲击。公众仍会通过V1的官方曝光、议程外曝光和学习成本路径更新信任。

## 8. 正式实验设计

计划的时延面板为：

- 条件：`v1_reference_3`、`conditional_p05_11`、`case_typical_22`、`conditional_p95_57`、`conditional_empirical_resample`；
- `alpha`：0.00至1.00，步长0.05，共21个水平；
- 共同随机种子：73000至73049，共50个；
- 单次规模：300名公众、300天；
- 总运行数：5×21×50=5,250。

经验重抽样必须使用与模拟主随机数相隔离的确定性抽样规则：每个种子从222条条件时延中抽一次并取整数天，同一随机种子的21个 `alpha` 共用这个时延。这样可以避免时延本身随 `alpha` 改变。

烟雾验证命令：

```powershell
python 07_version2_uk_petition/02_experiment_code/run_v2_experiment.py --scope smoke --workers 1 --overwrite
```

正式实验命令：

```powershell
python 07_version2_uk_petition/02_experiment_code/run_v2_experiment.py --scope formal --workers 8
```

截至本模型卡版本，烟雾矩阵完成5个条件×3个 `alpha`×1个种子，共15次运行和90个事件；单元测试11/11、独立发布QA 9/9通过。正式5,250次尚未运行，烟雾输出只用于软件验证。

## 9. 主要输出与解读

### 9.1 制度过程

- `response_threshold_step`：首次满足回应门槛；
- `response_due_step`：模型排定的到期步；
- `response_executed_step`：实际发布步；
- `realized_response_delay_days`：执行步减触发步；
- `response_queue_age_days`：仍待回应时已经等待的天数；
- `debate_threshold_step`：达到100,000制度门槛的步，而不是实际辩论日。

### 9.2 热度过程

- `petition_heat`：焦点请愿在本步衰减前的热度；
- `response_heat_delta`：回应执行瞬间由热度乘数造成的变化；
- `petition_heat_auc_pre_7_days` 与 `petition_heat_auc_post_7_days`：回应前后各7天热度的描述性积分。

前后积分是模型内描述量，不是因果估计。因为回应不是随机分配，且同一步还有推荐、公众互动和自然衰减。

### 9.3 系统结果

- `mean_agenda_divergence`：末100步平均议程偏离；
- `system_stability`：末100步议程偏离的总体方差，值越大表示波动越强，字段名不能按字面解释为“越大越稳定”；
- `storm_time_share`：末100步处于风暴状态的比例；
- `mean_trust`：末100步模型内平均政府信任。

这些变量是模型输出，不是英国请愿数据中的直接观测。

## 10. 验证与质量控制

建议每次发布前从仓库根目录执行：

```powershell
python -m unittest discover -s 07_version2_uk_petition/04_tests -v
python 07_version2_uk_petition/06_reproducibility/validate_v2.py
```

最低验收包括：

- V1核心哈希不变，V2父模型副本逐字节相同；
- 配置边界有效，相同种子完全可重复；
- 10,000门槛按“大于等于”一次触发；
- 同一请愿只排程、发布一次回应；
- 回应执行步等于触发步加时延；
- 请愿在开放期内不会因低热度被清理，关闭后不再推荐；
- 合成模式每名公众最多签一次，关闭后无新签署；
- 222条输入时延均为正且700024存在；
- 经验抽样对同一随机种子的所有 `alpha` 固定；
- 正式面板若存在，应有5,250个唯一主键且每格50次；
- 输出只写入V2子树。

## 11. 局限与风险

1. **案例外推风险。** 英国议会制度、政治环境和平台结构不能直接代表中国数字政府。
2. **选择条件风险。** 222条样本条件于已回应，无法观察未回应风险集的完整等待分布。
3. **聚合数据风险。** 官方API没有个体曝光、逐日完整签名轨迹、偏好面板或信任量表。
4. **平台错配。** 英国请愿网站不是已知采用本模型个性化推荐公式的平台。
5. **时间标定风险。** 一步约为一天只直接服务于回应时延；V1其他逐步参数未做每日重新标定。
6. **单案选取风险。** 700024在回应时延上接近中位数且制度链完整，但最终超过100,000签名，不代表所有维度上的典型请愿。
7. **政策语义风险。** “已回应”不代表“诉求被采纳”“问题已解决”“热度下降”或“信任上升”。
8. **因果解读风险。** V2是机制情景模拟，不是基于自然实验或随机实验的因果识别。

## 12. 透明报告要求

报告V2结果时应同时披露：模型版本和提交、触发模式、时延情景、`alpha`、种子、样本范围、热度乘数、直接信任信号、政策立场、运行次数、QA状态及输出哈希。至少在图注或方法中写明“222条时延条件于已获得政府回应”。

不能写：

- 英国数据验证了V1的0.15注意力份额门槛；
- 10,000签名等于20%的模拟公众；
- 22天是所有请愿的无偏平均回应时间；
- 英国案例估计了真实 `alpha`、偏好漂移或信任机制；
- 政府回应导致热度下降或信任上升；
- 烟雾验证结果是正式实验发现。
