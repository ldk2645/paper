# Version 2 相对 Version 1 的变更记录

## 版本原则

Version 2采用新增目录和新增模块，不直接修改或覆盖冻结的Version 1。`01_model/base_v1.py`应与仓库 `01_model_core/model.py` 逐字节一致；V2的所有新机制都位于 `01_model/model_v2.py`。

冻结V1核心SHA-256：

```text
AB78E6C64AFB6FD487E40A48FBBCD1B09A84EE3FBC9085530F8833DE3543D7EC
```

V2模型标识：

```text
2.0.0-uk-petition-case
```

## 变更总览

| 模块 | V1 | V2 | 变更性质 |
|---|---|---|---|
| 研究对象 | 一般性主题级信息流 | 一般信息流＋一个焦点电子请愿 | 新增案例对象 |
| 时间语义 | 抽象时间步 | 一个时间步约定为一天 | 情景时钟约定 |
| 政府回应触发 | 本步某主题自发注意力份额严格大于0.15 | 焦点请愿的一次性制度门槛 | 替换回应触发器 |
| 回应时延 | 默认3步 | 默认22天，另有3/11/22/57/经验抽样 | 案例约束情景 |
| 回应对象 | 同主题全部自发信息 | 只作用于焦点请愿，并生成政府回应信息 | 目标精确化 |
| 重复回应 | 主题可再次越阈并排程 | 同一请愿最多排程、执行一次 | 状态机约束 |
| 政策立场 | 未显式编码 | `accepted` / `partially_accepted` / `no_policy_change` | 新增且与发布分离 |
| 热度效应 | `response_strength`同时作为热度保留与信任输入 | `response_heat_multiplier`独立控制请愿热度 | 解耦 |
| 直接信任效应 | 与回应热度效应耦合 | `direct_response_trust_signal`独立进入信任更新 | 解耦 |
| 签署行为 | 无 | 合成模式中曝光后概率签署、每人最多一次 | 新增反事实机制 |
| 10,000/100,000门槛 | 无 | 案例日历事件或合成支持门槛 | 新增制度事件 |
| 请愿生命周期 | 无 | 开放、待回应、已回应、可进入辩论、关闭 | 新增状态 |
| 事件日志 | 无独立事件表 | 一次性门槛、排程、回应、关闭等事件 | 新增审计输出 |

## 继承而未改写的V1机制

以下机制仍使用V1实现：

- 公众偏好、情绪性、数字素养、学习成本和政府信任的初始化；
- 平台推荐分数 `alpha × 归一化热度 + (1-alpha) × 偏好相似度`；
- 每人每步的注意力预算；
- 公众互动概率、互动后信息热度累加；
- 连续主导议题导致的偏好漂移；
- 自发信息生成；
- 热度衰减与普通低热度信息清理；
- 议程偏离、舆情风暴、学习成本和信任更新；
- 末100步摘要规则。

“继承”不等于“经英国数据确认”。特别是 `heat_decay`、`preference_drift_rate`、学习成本和信任系数仍是V1参数；一个时间步被解释为一天后，这些逐步参数获得每日运行语义，但没有被英国请愿数据重新估计。

## 参数变更及来源

### 来自700024单案观测

| 字段 | V2值 | 说明 |
|---|---:|---|
| `petition_id` | 700024 | 官方编号 |
| `petition_open_step` | 0 | 正式公开日为原点 |
| `observed_initial_signatures` | 5 | 英国请愿提交需5名支持者的制度起点；不是700024公开时签名快照 |
| `observed_response_threshold_step` | 14 | 约14.28天达到10,000，取整数步 |
| `observed_debate_threshold_step` | 177 | 达到100,000的整数日历步 |
| `petition_close_step` | 182 | 正式公开至关闭的整数日历步 |
| `observed_debate_step` | 237 | 实际议会辩论日，仅作元数据 |
| `observed_final_signatures` | 110,519 | 官方关闭后快照 |
| `response_disposition` | `no_policy_change` | 回应没有采纳主要禁令诉求 |

### 来自222条已回应请愿的条件样本

| 情景 | V2整数天数 | 统计量 |
|---|---:|---|
| `conditional_p05_11` | 11 | 条件回应时延P5约11.07天 |
| `case_typical_22` | 22 | 条件回应时延中位数约21.65天，亦接近700024的21.79天 |
| `conditional_p95_57` | 57 | 条件回应时延P95约56.52天 |
| `conditional_empirical_resample` | 随种子 | 从222个正时延中抽样后取整数天 |

样本来自 `state=with_response` 查询并经过完整时间戳与固定窗口筛选，因此这些数值是“在已回应记录中的条件时延”，不是所有请愿的无条件等待时间，也不能估计回应概率。

### 英国制度规则

- 10,000个签名触发政府回应程序；
- 100,000个签名使请愿进入议会辩论考虑程序。

这些是现实绝对数，只有 `observed_calendar` 模式按绝对数记录。V2没有把10,000或100,000换算为300名模拟公众。

### 仍属反事实或研究设计的参数

| 字段 | 默认值 | 性质 |
|---|---:|---|
| `alpha` | 0.50，正式扫描0.00–1.00 | 案例不能识别的推荐权重 |
| `synthetic_support_threshold_fraction` | 0.20 | 合成公众中的支持比例，不是现实换算 |
| `signature_probability_on_exposure` | 0.02 | 曝光后的合成签署概率 |
| `petition_initial_heat` | 1.0 | 初始化假设 |
| `petition_emotional_intensity` | 0.65 | 内容属性假设 |
| `response_heat_multiplier` | 1.00 | 回应对热度的反事实作用 |
| `direct_response_trust_signal` | 0.00 | 回应对信任的直接反事实信号 |
| `response_information_initial_heat` | 0.0 | 回应信息初始化假设 |

## 两个触发模式的边界

### `observed_calendar`

- 输入是700024观测日历；
- `observed_signature_count`依次更新为5、10,000、100,000、110,519；其中5来自提交支持者制度规则，后三个是案例门槛/快照；
- 回应门槛在第14步触发；
- 该模式用于案例约束时延实验；
- 300名公众的模拟签署数组不产生上述现实签名数。

### `synthetic_unique_support`

- 输入是模拟曝光与概率签署；
- 每名模拟公众最多签一次；
- `cumulative_unique_signers / population_size`达到合成阈值后触发；
- 该模式用于反事实机制检验；
- 其支持人数与现实10,000签名没有比例换算关系。

同一运行只能选择一种模式。两个模式的字段保留是为了审计，不是为了把两种计量单位合并。

## 回应链的结构性修正

V1把回应的多种含义压缩到同一数值效果。V2将其拆为：

1. `response_threshold_reached`：门槛越过；
2. `government_response_scheduled`：模型建立待回应任务；
3. `government_response_published`：到期后发布一次正式回应；
4. `response_disposition`：回应的政策立场；
5. `response_heat_multiplier`：对焦点请愿热度的独立乘数；
6. `direct_response_trust_signal`：当步进入信任更新的独立信号。

默认的700024配置是“发布了回应＋未改变政策＋不强制降温＋不赋予直接增信”。这是最小承诺基准，不表示现实回应对热度或信任的因果效应为零。

## 输出变更

V2在V1逐步指标和摘要上新增：

- 请愿状态、可见性和热度；
- 请愿曝光、互动和合成唯一签署者；
- 现实签名里程碑；
- 回应是否待办、队列年龄、到期日与当步执行标记；
- 回应立场、热度乘数、当步热度变化与直接信任信号；
- 是否达到辩论门槛；
- 回应前7天和回应后7天的请愿热度积分；
- 独立事件表及每个事件的证据类型。

详细字段见 `05_documents/DATA_DICTIONARY_V2.md`。

## 正式实验与既有结果的关系

V2计划的正式时延实验是5个时延条件×21个 `alpha`×50个共同随机种子，即5,250次新运行。它与V1的5,250次正式消融实验只是行数相同，研究问题、条件定义和输出路径不同，**不得合并或相互替代**。

当前完成了15次烟雾运行（5个条件×3个 `alpha`×1个种子）、11项单元测试和9项独立发布QA；V2正式5,250次运行尚未执行。任何烟雾输出都只能证明管道可运行，不能被写为正式效应量、置信区间或论文结论。

## 兼容性与不变项检查

V2的发布检查至少包括：

1. 仓库V1核心哈希仍等于冻结值；
2. V2的 `base_v1.py` 与V1核心逐字节相同；
3. V2不向V1数据、图件或结果目录写文件；
4. 相同配置与种子产生相同结果；
5. 一案只排程并执行一次回应；
6. 回应执行步严格等于触发步加设定时延；
7. `observed_calendar` 与 `synthetic_unique_support` 的单位和字段不互相替代；
8. 正式面板若运行，应为5,250个唯一主键且每格50次；
9. 经验抽样时延对同一种子的21个 `alpha` 保持固定。
