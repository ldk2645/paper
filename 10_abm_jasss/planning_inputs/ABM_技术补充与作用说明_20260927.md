# 反向黑箱 ABM：当前缺口、技术补充与作用说明

**用途：** 同步技术侧，作为下一轮 ABM 开发与正式实验放行依据。  
**核心原则：** 当前模型不缺更多理论机制，缺的是**识别层、反事实层、记录层与复现层**。不要继续增加学习成本、数字政府等复杂变量。

---

## 1. 当前模型已经有什么

当前版本已经具备：

- 政府阈值触发；
- 有限处理容量；
- 排队与执行延迟；
- hard / selective / wait 等回应策略；
- 政府回应内容发布；
- 回应对议题热度的风格化调节；
- 常规官方议程发布；
- 情绪差异开关；
- 偏好漂移开关；
- 信任状态、信任更新与信任反馈开关；
- 推荐排序中的热度权重 α；
- 已完成开发性 pilot。

因此下一阶段的目标不是“让模型更复杂”，而是让模型能够严格区分：

\[
P_t ightarrow E_t ightarrow S_t ightarrow \hat P_t^G ightarrow R_{t+\delta}
\]

其中：

- \(P_t\)：公众当期潜在偏好；
- \(E_t\)：平台实际曝光结构；
- \(S_t\)：政府现实中可观察的平台聚合信号；
- \(\hat P_t^G\)：政府根据有限信息形成的公众偏好估计；
- \(R_{t+\delta}\)：经过制度过程后的政府回应。

---

# 2. P0：正式实验前必须补齐

## P0-1 独立政府感知模块 `government_sensing`

### 当前问题

当前政府基线基本直接复制当期曝光，因此：

\[
TV(P_t,S_t)
\]

与

\[
TV(P_t,\hat P_t^G)
\]

容易机械重合。

这意味着当前模型还不能区分：

1. 平台把公众“呈现错了”；
2. 政府又在读取平台信号时“判断错了”。

### 技术要求

单独生成并保存：

```text
P_true(t)
E_exposure(t)
S_platform(t)
P_hat_gov(t)
```

Baseline 政府只能根据过去若干窗口的 `S_platform` 估计公众偏好。

感知规则至少允许配置：

```text
observation_window
smoothing
observation_noise
sampling_rate
update_frequency
```

### 作用

真正拆开：

```text
公众偏好
→ 平台表示失真
→ 政府感知误差
```

这是 Reverse Black Box 在模型内成立的核心。

---

## P0-2 区分 Exposure 与 Government-visible Signal

### 当前问题

不要继续让 `A(t)` 同时表示“用户实际看到什么”和“政府能够看到什么”。

平台内部曝光与政府可见热度不是同一个变量。

### 技术要求

建议固定：

```text
P_t = latent/current public preference
E_t = actual platform exposure
S_t = government-visible aggregate signal
P_hat_t = government estimate
```

例如政府只能观察：

```text
topic engagement share
public trend score
aggregate heat
historical public metrics
```

而不能直接观察完整的个体级 `E_t`。

### 作用

允许分别分析：

\[
D(P,E)
\]

平台实际分配注意力是否偏离公众偏好；

\[
D(P,S)
\]

政府能看到的平台表征是否偏离公众偏好；

\[
D(P,\hat P)
\]

政府最终判断又偏离多少。

---

## P0-3 Government Information Whitelist

### 当前问题

如果 government agent 在 baseline 中能够直接读取：

```text
citizen.preference
true exposure probability
future state
latent preference
hidden ranking state
```

那么 Reverse Black Box 会在代码层被破坏。

### 技术要求

为 government agent 建立明确的信息白名单。

Baseline 只允许读取：

```text
historical observable platform signal
government internal queue/state
past government actions
allowed public aggregate statistics
```

禁止读取隐藏真值。

每个 tick 最好记录：

```text
government_information_packet
```

用于事后审计。

### 作用

防止 information leakage，保证政府感知误差是真正由信息约束产生，而不是模型作者人为加噪声制造。

---

## P0-4 双重遮蔽 2×2

### 设计

两个因素：

```text
Preference Information: absent / available
Algorithm Information: opaque / transparent
```

形成四格：

| | 算法不透明 | 算法透明 |
|---|---|---|
| 无独立偏好信息 | Baseline | Algorithm transparency only |
| 有独立偏好信息 | Preference information only | Both available |

### 注意

`Preference Information = available` 不应默认等于真值。

正式主实验应模拟有限调查信息，例如：

```text
survey_sample_size
survey_update_frequency
sampling_error
nonresponse_bias
measurement_noise
```

Perfect Preference Oracle 单独作为理想上界，不属于现实政策处理。

### 作用

分别识别：

- 看不到公众真实偏好造成多少损失；
- 看不到平台排序机制造成多少损失；
- 两种信息改善是否互补；
- 算法透明是否在没有独立偏好数据时仍然有治理价值。

---

## P0-5 Algorithm Transparency 必须改变政府推断过程

### 当前问题

仅仅告诉政府：

```text
alpha = 0.7
```

或者展示推荐公式，不等于检验算法透明。

### 技术要求

透明组至少获得：

```text
ranking rule
ranking parameters
```

并在政府估计器中实际使用这些信息。

例如：

```text
Opaque:
estimate ranking mechanism from predefined candidate-rule prior

Transparent:
replace mechanism uncertainty with disclosed ranking rule/parameters
```

两组必须：

- 使用相同公开历史；
- 使用相同计算预算；
- 使用相同正则化/估计框架；
- 唯一主要差异是排序机制是否已知。

### 作用

真正检验：

> 算法透明本身能否提高政府对公众偏好的恢复能力？

注意：**透明组不要求结果一定更好。** 无效果同样是合法结果。

---

## P0-6 Snapshot / Fork 同状态反事实

### 当前问题

两个独立 simulation run 结果不同，可能来自：

- 初始状态差异；
- 内容生成随机性；
- citizen choice 随机性；
- 随机事件差异。

因此不能直接把差异全部解释为 intervention effect。

### 技术要求

在指定 \(t^*\) 保存完整：

```text
system_state
citizen states
content pool
government queue
trust states
preference states
heat states
RNG states
```

形成：

```text
state_snapshot
```

随后从同一个 snapshot fork 多个后缀世界。

### 作用

实现真正的：

\[
S_{t^*}ightarrow
egin{cases}
Treatment_1\
Treatment_2\
Treatment_3\
...
\end{cases}
\]

使不同干预面对相同母状态。

---

## P0-7 同状态干预组

从同一 snapshot 至少生成：

```text
A. No intervention
B. Better preference information
C. Faster response
D. Greater administrative capacity
E. Ranking intervention
```

如有必要可另加：

```text
F. Stronger response
```

但不要无限增加处理组。

### 作用

直接回答论文最核心的治理问题：

> 政府究竟是“看错了”“来晚了”，还是“手里的工具作用在错误层级”？

尤其可以比较：

```text
Better sensing
vs
Faster administration
vs
Upstream architecture intervention
```

这是 “Structural Limits of Government Responsiveness” 的主要反事实证据。

---

# 3. 三层 Primary Outcomes

正式实验至少固定三个层级。

## Outcome 1：Platform Representation Gap

例如：

\[
D_{PS}(t)=TV(P_t,S_t)
\]

作用：

> 平台可见信号与公众当期偏好之间差多少？

---

## Outcome 2：Government Perception Error

\[
D_{PG}(t)=TV(P_t,\hat P_t^G)
\]

作用：

> 政府最终理解的公众，与公众当期偏好差多少？

---

## Outcome 3：Response Misalignment

不要只设计一个含混的综合“治理绩效指数”。

建议至少拆成：

```text
targeting_error
waiting_time
unmet_priority
execution_count
response_completion
```

### 作用

区分：

```text
政府选错回应对象
```

和

```text
政府对象没选错，但执行时已经太晚
```

这是理论上的 sensing failure 与 administrative lag 的关键区别。

---

# 4. P1：正式冻结前的重要补充

## P1-1 保存 Trigger Preference 与 Execution Preference

每次政府回应保存：

```text
P_trigger
P_execution
trigger_time
execution_time
target_issue
```

分别计算政府行动相对于两者的错配。

### 作用

观察：

> 政府在作出决定时可能是对的，但执行时公众偏好已经发生变化。

这直接对应 temporal mismatch。

---

## P1-2 真正实现 Zero Administrative Delay

当前 `government_delay >= 1`。

不能简单把参数改成 0。

需要重新定义同一 tick：

```text
observe
→ infer
→ decide
→ execute
→ platform ranking
→ citizen consumption
```

的严格先后。

### 作用

建立真正的反事实：

> 如果行政过程能够立即回应，剩余治理错配还有多少？

从而区分：

```text
sensing problem
vs
administrative delay problem
```

---

## P1-3 RNG Stream 拆分

至少拆成：

```text
rng_content
rng_citizen
rng_government
rng_intervention
```

并保存各自 seed/state。

### 作用

不同 treatment 改变函数调用次数后，“同一个整数 seed”不再天然代表同一个外生世界。

拆分随机流可以提高 paired comparison 和 snapshot/fork 的可信度。

---

## P1-4 Full Heat-off 对照

`alpha = 0` 只表示排序分数不使用 heat。

它不等于：

```text
no algorithm
```

也不等于：

```text
no heat feedback
```

需要另设完整 heat-channel-off 条件，例如：

```text
heat_floor = 0
```

或改用只按年龄清理内容。

### 作用

区分：

```text
关闭热度排序
```

和

```text
关闭整个热度反馈通道
```

避免论文错误解释 α=0。

---

## P1-5 Trust 模块化

保留：

```text
trust_update on/off
trust_feedback on/off
```

允许：

```text
frozen trust
```

### 作用

检验 trust 到底是：

```text
feedback mechanism
```

还是：

```text
secondary/downstream outcome
```

主论文的三个核心 outcome 不应依赖 trust 才能计算。

如果 trust 不改变主结论，可以降到附录。

---

# 5. Monte Carlo 与正式运行

## 5.1 不固定“每格 50 seeds”

P0/P1 完成后重新跑独立 precision pilot。

根据主对比的 run-to-run variance 决定正式重复数。

例如依据：

```text
target CI half-width
Monte Carlo standard error
```

确定 seeds。

### 作用

避免：

- seeds 太少；
- 无意义浪费计算；
- 根据显著性临时补 seeds。

---

## 5.2 正式 seeds 与开发 seeds 分开

开发阶段使用过的 seeds 不进入 formal main analysis。

正式设计冻结后，一次性生成正式 seed list。

---

# 6. Metadata 与复现

每个 world 至少保存：

```text
run_id
code_version
config_hash
seed
rng_stream_seeds
scenario
alpha
N
T
initial_condition
treatment
snapshot_id
parent_run_id
government_information_condition
algorithm_information_condition

```

### 作用

确保任何正式结果都能追溯到：

```text
哪一版代码
+ 哪个配置
+ 哪个随机种子
+ 哪个母状态
+ 哪个处理条件
```

# 7. 必须新增的 Tests / Invariants

至少检查：

1. 所有 preference / exposure / signal 分布合法且和为 1；
2. Baseline government 无法读取 latent preference；
3. Baseline government 无法读取隐藏 ranking state；
4. 2×2 四格实际获得的信息包不同；
5. Transparency 信息确实进入估计器；
6. Snapshot 恢复后母状态完全一致；
7. Fork 前状态完全相同；
8. 无 intervention 时 fork 能复现一致轨迹或满足预设随机同步规则；
9. No drift 条件下 preference 不发生漂移；
10. Frozen trust 条件下 trust 不更新；
11. No response 不删除常规政府发布；
12. `alpha=0` 与 full heat-off 是不同实验条件；
13. response 未执行时不把 mismatch 强行记录为 0；
14. censored recovery 正确标记。

### 作用

防止出现：

> 代码能够运行，但实验语义实际上已经错了。

---

# 8. P0 完成后的 Sanity Batch

不要立即正式大跑。

先做小规模 sanity。

至少确认：

### S0-1

\[
P_t,\ S_t,\ \hat P_t^G
\]

不再按定义机械相等。

### S0-2

双重遮蔽 2×2 的四个条件确实改变政府可用信息及推断过程。

### S0-3

同一个 snapshot 能正确 fork，不同 intervention 从完全相同母状态开始。

### S0-4

验收标准只检查：

```text
implementation semantics
permissions
state restoration
recording correctness
```

**不要求：**

```text
透明一定改善
偏好信息一定改善
行政提速一定改善
四组结果必须显著不同
```

结果方向必须由正式实验决定。

---

# 9. 当前不要再增加什么

本轮不要继续增加：

- learning cost；
- digital government index；
- 新的 trust 方程；
- 更多 agent 类型；
- 新的治理绩效综合指数；
- 为复现旧稿而硬拟合 α≈0.55；
- 为得到“相变”而调参数。

当前任务是**识别升级，不是复杂度升级**。

---

# 10. 为什么必须补这些

最终模型要能够识别三段完全不同的过程：

\[
oxed{P_t ightarrow S_t}
\]

### Platform Representation

平台可见的“公众”与公众真实/当期偏好差多少？

---

\[
oxed{S_t ightarrow \hat P_t^G}
\]

### Government Sensing

政府面对不完整、算法中介的信息时，又额外判断错多少？

---

\[
oxed{\hat P_t^G ightarrow R_{t+\delta}}
\]

### Government Responsiveness

政府即使形成判断，行政时滞、容量和工具限制又产生多少回应错配？

---

只有把三段拆开，论文才能真正回答：

> **政府是看错了、来晚了，还是即使看对并加速回应，下游工具仍无法完全修复上游注意力架构造成的错配？**

这也是 Reverse Black Box 与 Structural Limits of Government Responsiveness 的核心识别逻辑。

---

# 11. 技术侧开发顺序

建议严格按以下顺序：

```text
Step 1
冻结 P / E / S / P_hat / R 的语义

Step 2
建立 government information whitelist

Step 3
实现 independent government sensing

Step 4
实现双重遮蔽 2×2

Step 5
实现 transparency 的实际推断规则

Step 6
实现 snapshot / restore / fork

Step 7
实现五组同状态 intervention

Step 8
实现三层 raw outcomes

Step 9
增加 permissions / invariants / restoration tests

Step 10
运行小规模 sanity batch

Step 11
实现 Zero Delay / RNG streams / full heat-off / trust modularization

Step 12
重新运行 precision pilot

Step 13
冻结 formal design

Step 14
正式 Monte Carlo
```

# 12. 正式运行放行条件

只有以下条件全部满足后，才进入正式大规模 Monte Carlo：

- [ ] `P / E / S / P_hat` 已严格分层；
- [ ] government baseline 不读取隐藏真值；
- [ ] 2×2 双重遮蔽已真实改变信息集；
- [ ] algorithm transparency 已进入实际推断程序；
- [ ] snapshot / restore / fork 测试通过；
- [ ] 同状态 intervention 可运行；
- [ ] 三层 primary outcomes 已冻结；
- [ ] response targeting 与 timing 已拆分；
- [ ] RNG streams 已确定；
- [ ] precision pilot 已完成；
- [ ] 正式 seed 数量已按精度冻结；
- [ ] formal config / code version / metadata schema 已冻结。

完成这些以后，ABM 才从“能运行的复杂模型”升级为：

> **能够识别 Reverse Black Box、政府感知误差与回应结构性边界的计算实验模型。**
